# 备份与恢复

画师应至少保留两份原画：创作设备与独立备份盘。网站只存展示版，任何导出都不能重建未上传的原画。

## 应用内容

后台“导出内容”下载合集、作品、双语资料和图片资源清单。演示模式导出可能包含 data URL；生产导出含 providerAssets 原始 key/fileId 及公开副本记录，仅管理员可见，请私下保存。短时预览 URL 会过期，长期恢复依赖文件ID和服务商资产。

## 数据库

```powershell
npx wrangler d1 export gallery --remote --output=gallery-backup.sql --config wrangler.toml
```

导出文件可能含私人元数据，应保存到用户选定的备份位置且不要提交公开仓库。定期在 ImageKit 中下载展示主文件和公开副本，保留 fileId/path 映射。

恢复先建立独立测试 D1，再将 SQL 导入该测试库：

```powershell
npx wrangler d1 execute gallery-restore --remote --file=gallery-backup.sql
```

命令前核对目标为测试库；不要覆盖生产库。恢复后核对合集数、作品数、中英文、封面/排序和文件引用，再检查公开图及私有预览。若资源重传产生新 fileId，需同步更新资源映射；不能仅导入元数据就声明图片恢复成功。

## 删除与恢复

回收站只软删除，恢复为草稿。合集永久删除前必须先处理其子作品。永久删除作品只清理没有其他作品引用的资产；如果外部图片服务删除失败，应用保留清理记录，可在回收站“未关联图片与待清理文件”区重试，也可调用管理 API DELETE /api/admin/assets/:id（JSON {}）。不用递归脚本盲目清空图片账户。

若发布上传的网络结果不明确且服务商尚查不到固定路径，清理会继续保留记录。此时人工核对文件 ID/路径和账户用量，确认没有尚在处理的远端任务后再处理；不要直接删除数据库记录掩盖可能残留的云文件。关闭/刷新上传页会丢失该页的内存重试检查点，请先核对已创建作品和未关联图片，避免重复上传。

真实恢复演练需要用户的云账户，目前文档提供操作步骤，不代表已执行。
